#A13 / A15 / A16 / A17 的说明（这四条都是被实测逼出来的）

这四条有一个共同点：初版都写成了"看起来更合理"的那一版，然后被读数证伪。

A13 —— 清场清到什么程度。 初版"BOSS 登场移除全部僵尸"，理由是关底被 78 只杂兵稀释时， 玩家读到的是"被围死"而不是"打不过 BOSS"。 但全清之后关底战最低血量 96.4%，难度峰跑到了 10:40 的第二场—— 关底成了过场。 正确规则是"清掉肉墙，留下机制"：只清用数量施压的三种， 毒池、自爆、跳跃仍在逼玩家走位。

A15 —— 一个常数配不平三个阶段。 初版 BOSS_PHASE_SPAWN_MUL = 0.35。刷怪预算按威胁值计， 而阶段 2 的出怪表是数量型（威胁 1.0-1.2）、阶段 3 是质量型（胖僵尸威胁 3.0）—— 同样预算，阶段 2 堆出的身体更多。结果三个阶段同倍率时难度曲线非单调。 现在按"反解出想要的场上只数（3 / 4.5 / 6）"分别定。

A16 —— 减伤不能叠乘。 叠乘的话罗恩 0.5 × 博姆 0.6 = 0.3，两个辅助同时开技就能把全队承伤压到三成， 配平直接崩。取 min 而不是连乘。

A17 —— 基础回血必须脱战才生效。 初版注释写的是"脱战回复"，代码却每帧无条件执行。 效果是给全队挂了一个常驻 1%/s 回血，把接触伤害整条抵消掉—— 三个 BOSS 战的血量曲线全部贴在 90% 以上，压力读数完全失效。 这不是数值问题，是注释和代码不一致的问题。

#A24 的说明（本轮唯一一处"故意留的不对称"）

五件套里，四件是对称的，一件不是。

控制手段 对抗属性 谁有
击退 / 击倒 稳固（英雄由 TGH 派生，僵尸是表值 stab） 双方
冻结 抗冻 freezeRes 僵尸有；英雄端未开
嘲讽 狡诈 cunning 僵尸有；英雄端未开
减速 （不设） —

减速是全游戏唯一没有对抗面的控制。 这是判断，不是遗漏， 写完就得摆在明处等否决：

  • 控制体系需要一层地板。如果每个控制都能被对抗，那么"控制流"就永远打不过 "堆抗性"，因为它总有一个数值天花板；留着减速这条缝隙，控制流才有一条 走到黑的路。
  • 反过来，地板也保证了不能被控制免疫完全堵死——僵尸里没有"减速免疫"这种东西， 冷冻枪对任何目标都有用，只是有用的程度不同。
  • 代价是减速会偏强。02-数值表.html §11.2 的对照组：护盾僵尸的综合控制抗性 0.58， 但它对减速的抗性同样是 0。这个代价本轮接受，靠冷却与持续时间配平， 不靠加一个 slowRes 字段。

霸体只免疫位移同理，但它是对称的收窄而不是不对称：霸体僵尸会被冻、会被嘲讽、 会被减速，只是不会被推走。这条把"霸体"从一个"免疫一切"的懒解法 降级成一个具体的、有明确答案的属性——打不动它就换冻结，而不是硬推。

#A29 / A30 的说明（两条都在"尽量少引入新东西"）

A29 —— 命令栏守住了 B6 的原始担心。 详见 §B 下方那段。 要点：三个按钮里两个是状态切换、只有一个是即时动作，且默认"自由"必须能通关。 它是效率旋钮。试玩时若发现玩家在战斗中频繁切命令，说明它已经越过那条线，要往回砍。

A30 —— 障碍只引入两条新通行语义，因为每多一条，core/terrain.ts 的 碰撞与视线判定就要多一个分支：

障碍 可破坏 挡人 挡弹 挡视线 语义
沙袋 / 铁丝网 ✓ ✓ ✗ ✗ 人能挡、子弹不挡
木墙 ✓ ✓ ✓ ✓ 可炸开
建筑（对照） ✗ ✓ ✓ ✓ 基准

沙袋与铁丝网共用同一格通行语义，木墙只是"可破坏的建筑"—— 所以新的枚举值只有两个，不是三个。实际摆放归 M2 的 core/terrain.ts，本轮只出表。

#A6 的说明（这条曾被我写错过）

初版设计稿把穿透写成"伤害再乘一个 (1 - pierce/(pierce+40)) 的减伤"——方向反了， 那会让穿透越高伤害越低。正确语义是穿透削弱目标护甲：

有效护甲 = 目标护甲 × (1 - pierce/(pierce+60))
最终减伤 = 有效护甲 / (有效护甲 + 100)

穿透值 60 时有效护甲减半。这样穿透是独立于攻击力的第三条成长轴， 而不是攻击力的一个换皮乘区。策划案里的公式已按此更正。

修订的理由与代价：

B2 的修订不是松动——"不做通用复活"这条守住了（run-sim.ts 里没有任何复活路径）， 唯一例外被做成了一个阵容决策：要不要为了这一条占掉一个位置、把 3 点专精全押在莉安身上。 它没有让"阵亡"失去意义，只是把它变成了一道选择题。

B5 的修订是这一轮风险最大的一条。一旦局外有数值强化， "卡住就回去刷"这条路就打开了——而本轮整个设计目标是"卡住只能换阵容"。 守住的机制是 SpecEffect 联合类型里刻意没有"新增伤害乘区"： 专精只能改公式的输入（属性/武器阶/技能参数/AI 参数/维度答案）， 不能改公式本身。这条约束由编译器执行，不是靠注释提醒。 代价：曾有 4 个顶层节点退成纯数值；C6-#3 已全部改为新本事（09 §5.4）。

B4 的第二次作废值得单独记一笔。 第一次作废（B 表上方）废掉的是"积分→等级"； 这一次废掉的是剩下的一半"金钱→武器阶"。原因是局外商店接手了"买什么"这件事： 既然武器阶可以由时间免费给，金钱就该去买别的角色买不到的东西（新武器；C6-#1 起为买断的装备本身）， 而不是去买一个所有角色都会随时间拿到的东西。三件事凑在一起才自洽—— 时间给所有人的（等级/阶）、金钱给选项（种类）、技能点给深度（专精与高级技能）。

#C. 已裁决（用户拍板，2026-09）

下面每条先留原建议，再写裁决。保留原建议是为了能看出用户否掉了什么、 以及否掉的理由——只写结论会丢掉判据。

#C1. 单局 15 分钟是否太长？

原建议：保留 15 分钟。模拟器实测积分在第 11-12 分钟到 5 级满级， 砍时长不解决"成型太晚"，真正的解法是降 LEVEL_COST。

裁决：✅ 15 分钟合适，不需要调整。

于是"成型太晚"这个问题保持原状不作处理。它是一个已知的、被接受的体验缺陷， 不是待办——若原型试玩后玩家确实在等结算，再议。

#C2. 是否需要"队员复活/救援"机制？

原建议：不做。队员一死小队 DPS 掉 20%，这是自动生效的失败惩罚，不需要额外机制。

裁决：✅ 不做统一复活机制，但可以做在某一个英雄角色的高级技能上。

落地为莉安的专精顶层节点「战地复活」（{ kind: 'revive', charges: 1 }）： 每局一次，把最近阵亡的队员以 50% 生命拉回战场。

这一条比"同意"更精确：它同时否掉了"通用机制"和"完全不做"两个极端。 所以 run-sim.ts 里不该出现复活路径，复活必须挂在角色数据上，走 SpecEffect。 唯一性（"全游戏独一份"）是设计的一部分，不是巧合——它让这一条成为一个阵容决策。

#C3. 装备/武器是否做"局外养成"？

原建议：不做数值养成。一旦引入局外数值，所有 BOSS 血量锚点都会失效。

裁决：✅ 武器不做局外养成，但做局内拾取解锁新武器。

前半句与建议一致。后半句是新增：局内可以捡到未解锁的武器，临时使用。

这条的意义比它看起来大：它让一次 run 之内的答案组合也能变化—— 中途捡到一把榴弹枪，就临时获得了 explosive 这个答案，可以应对突然出现的重甲波。 这是"局内 build"与"局外 build"的接缝（09-角色与成长.html §6.3）。

⚠️ 本轮（2026-09）部分作废。 上面这条裁决的前提是"局内有购买动作"， 而现在局内已经是零购买（A25）。"拾取解锁武器"这一半保留—— 它描述的是战场上捡到，与购买无关，而且它对"局内零购买"是正面的补充： 局内唯一能改变你答案组合的途径就是捡。

作废的是原先挂在 C3 上的那半句"待确认：是否允许替换主武器"—— 现在这个问题变了：既然武器种类本身要靠局外解锁（A26）， 拾取到的武器应该是临时副武器（到本局结束），否则"解锁"就失去了重量。 这一条记为下方 §E 的待确认项，不在本轮拍板。

#D. 已发现但不建议现在解决的问题

#D0. 13 个维度只收敛出 1 条真约束（本轮新增，最重要的一条）

用户要求"每种挑战不止有单一方案，而是有很多种组合"。哨兵枚举了全部 C(12,5) = 792 套阵容来验证，结果是这条只完成了下限：

最紧的一关也放行 92.9% 的阵容；87.5% 的阵容能覆盖全部 13 维
82 关里有 38 关并列在同一个门槛（736 套）

原因是结构性的：5 名队员、每人平均能回答 8.4 个维度，并集自然铺满全集。 "能不能进"这件事基本是免费的。 进一步算下来，真正约束阵容的只有 迟滞和毒区两个维度，而它们由同一批 4 个角色回答：

迟滞 = 毒区 = { 罗恩, 凯, 薇拉, 莉安 }

所以"2 个检查点"实际是同一个检查点数了两遍——整个 13 维体系收敛成 1 条约束。

本轮新增的第 13 维「控制抗性」让这条更糟，不是更好： 它是 12/12 全员可答， 零约束力（02-数值表.html §11.4 如实记着）。加这一维的理由不是"增加约束"， 是"给已有的控制手段一个对抗面"——目标不同，不要拿它给 D0 洗白。

这条不是待办，是边界，和 D1 同类。 哨兵能证明的是"维度没有死胡同" （每个维度 ≥3 种答案形状、≥2 个定位可答），不能证明用户要的多样性。 决策清单里如实记着，不拿 792 这个数字当背书。

真正的量法是把"能不能答"换成"答得好不好"——同一维度下不同答案的效率差， 需要 M2 把维度折进刷怪与承伤模型。当前架构下最便宜的中间步骤是 给每个 AnswerTag 对每个维度配效率系数（15×13 系数表）， 不需要动模拟器（09-角色与成长.html §7.4）。

#D1. 模拟器结构性无法验证"阵亡"这个难度目标

实测：阶段 3 常规段均场上有 9.8 只僵尸， 但其中贴身（进入攻击距离）的有 0 只——占比 0%。

区间                    均场上      均贴身      贴身占比
常规 0:00-5:00          3.2        0.0        0%
BOSS1 5:00-6:30         4.7        1.6        33%
常规 6:30-10:00         26.0       0.0        0%
BOSS2 10:00-11:30       7.8        4.3        44%
常规 11:30-15:00        9.8        0.0        0%
BOSS3 15:00-16:30       4.2        3.4        86%

一局平均总承伤 54,438   vs   小队满级总有效生命 70,560

僵尸从 25 格（视口边缘）出发，在走近的路上就被打死了。 所以"阵亡"在本模拟器里结构性地几乎不可能发生—— 140 次运行 / 7 套阵容，只有 5 次阵亡，且全部集中在"单坦四输出"这一套上。

注意 5 次 ≠ 0 次。上一版这里是 0/140，六属性重配之后 脆皮阵容的血量池被拉开，"最低血量"那一列从 30 个百分点的跨度变成 50 个， 于是终于出现了真实的减员。这是本轮少有的、哨兵自己长出来的新信号， 但它仍然只说明"冗余度有后果"，不说明"难度对不对"。

原因是三个简化叠在一起（详见 02-数值表.html §10）：

简化 后果
地图抽象成一维距离 所有僵尸从同一个方向来，没有包围
索敌是单点最近目标 5 个人不会分头堵不同方向
队员完全不走位 等于假设玩家每一次走位决策都正确

三条叠加 → 小队输出 100% 集中在唯一来向上 → 前沿永不被压到脸上。

这条不是待办，是边界。 模拟器是数值哨兵： 回答"配平是否自洽"（答：自洽），不回答"是否有难度"（回答不了）。 后者必须真人试玩。

早期版本这条写的是"需要 390 只僵尸同时贴身才能打穿队伍"。 那个算法（EHP ÷ 接触 DPS）本身没错，但它算的是一个永远不会发生的场景—— 真正的约束不是"打不打得穿"，是"僵尸根本走不到"。换成实测贴身占比才有意义。

#D2. 阶段 1 进入时 DPS 只有 BOSS 需求的 0.79x （已作废，但留下半个）

这条已经作废，留着是为了记住它是怎么来的。

初版按"进入阶段 1 时"（1 级 / 0 阶武器）算小队 DPS， 得出"阶段 1 只有 BOSS 需求的 0.79x，打不动"。

但 BOSS 1 在 5:00 才登场，那时小队已经不是 1 级了。按正确的时刻重算：

阶段 登场等级 武器阶 小队 DPS BOSS 需求 比值
1 3 1 1,565 1,617 0.97x ⚠
2 4 1 1,528 1,556 0.98x ⚠
3 5 2 1,836 1,567 1.17x ✓

教训：算比值时必须锁定"哪个时刻"。 用一个不该用的时刻做分母， 会得出一个看起来很像真的假警报，而它会掩盖真正的问题。

但这一轮 ⚠ 回来了，而且它不是配平问题，是判据问题。 六属性重配后阶段 1 / 2 的比值掉到 1 以下（上一版是 1.07x / 1.21x / 1.12x）。 分母取的是瞬时常驻 DPS，而实测三个 BOSS 分别在 31.0s / 45.8s / 51.2s 击杀， 对 30/45/60 秒的目标偏离 +3.3% / +1.8% / -14.7%，全部落在 ±15% 容差内 （02-数值表.html §6.3）。也就是说：常驻输出确实不够，但加上技能窗口就够了—— 而"靠技能窗口"本来就是设计意图。所以 < 1x 标的是判据本身有偏， 不是配平失衡。这条不该再当门槛用，除非改成"技能窗口开启后的均值 DPS"。

同一批错误里还有一条更严重的：§6.2 的校准表曾经手填等级， 而实测是 [3,4,5]——于是"校准表全部通过"和"BOSS 1 十八秒就死"同时成立。 现在校准表由模拟器自己的 bossReport 驱动，不再手填。
