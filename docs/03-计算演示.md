# 03 计算演示

> 本文把**一个角色从一级属性算到实战 DPS**的全过程展开，每一步都能用计算器复核。
> 目的不是展示算术，是证明 `src/data/*.ts` 里的公式是**可解释**的——
> 任何一个数字，玩家问"凭什么"，都能沿这条链走回属性表。
>
> 复算脚本：`node _calc.ts`（临时演示文件，可随时重建）。
> 所有中间值都由 `src/sim/combat.ts` 的真实实现产出，不是手抄的。
>
> **本轮（架构调整）本文一个数字都没改。** 挑战维度、场景关卡、专精树
> 都不进这条公式——专精只能改公式的**输入**（属性/武器阶/技能参数），
> 不能新增乘区，所以这条链对 82 个子关卡逐一成立
> （`04-技术框架.md` §2.1.2 说明这条约束为什么由编译器执行）。
>
> 唯一一处细节变化：**三个 BOSS 的登场顺序按场景轮换**
> （`scenes.ts` 的 `bossStages`，例如军事禁区是卡俄斯先来）。
> 本文用卡俄斯演示，是因为它护甲最高（480），对穿透的检验最严格——
> 它在城市废墟与原始丛林仍然压轴，在军事禁区则会第一个登场，
> 那时队伍等级更低、穿透更低，是更硬的关。

---

## 0. 演示的设定

| 项 | 值 | 为什么选这个 |
|---|---|---|
| 角色 | 鹰眼·薇拉 | 狙击手，穿透型，最能体现"第三条成长轴" |
| 等级 | 5（满级） | 关底 BOSS 登场时的实际等级 |
| 武器阶 | +2（满阶） | 同上 |
| 目标 | 尸潮之主·卡俄斯 | 关底 BOSS，480 护甲 / 重甲 |

**选最难的组合做演示**：如果穿透机制对 480 护甲的目标成立，对其他目标自然也成立。

---

## 1. 第一步：一级属性 → 派生属性

薇拉的一级属性（`src/data/characters.ts`）：

```
STR 34    AGI 36    TGH 14    INT 16      合计 100
```

等级成长系数：

```
g = 1 + 0.08 × (5 - 1) = 1.32
```

**注意这里有一处容易算错的地方**——`atkMul` 用的是**未缩放**的力量：

| 派生 | 公式 | 代入 | 结果 |
|---|---|---|---|
| `atkMul` | `1 + STR × 0.02` | `1 + 34 × 0.02` | **1.680** |
| `levelDmgMul` | `1 + 0.25 × (L-1)` | `1 + 0.25 × 4` | **2.00** |
| `hasteMul` | `1 + AGI×g × 0.01` | `1 + 47.52 × 0.01` | **1.4752** |
| `critRate` | `0.05 + AGI×g × 0.004` | `0.05 + 47.52×0.004` | **0.2401** |

**为什么 `atkMul` 不用缩放后的力量？**

因为 `atkMul` 带一个 `+1` 基数。若让等级去缩放力量，
`STR` 从 34 涨到 44.88 只会让乘区从 1.68 到 1.90（**+13%**），
完全跟不上关卡的缩放需求。所以等级收益拆成独立的 `levelDmgMul`（**每级 +25%**），
玩家看得见、算得清。**同一个等级成长，两条路径差 4 倍。**

> 敏捷则相反：它只进 `hasteMul` / `critRate` / `moveMul`，这些乘区没有 `+1` 基数，
> 所以**必须**用缩放后的值，否则敏捷就不成长了。

## 2. 第二步：武器与武器阶

```
狙击枪：基础伤害 700   射速 0.35/s   弹匣 5   换弹 2.5s   穿透 80   暴击 +15%
```

武器阶加成（`src/data/weapons.ts`）：

```
伤害 × (1 + 0.35 × 阶)      穿透 × (1 + 0.20 × 阶)
```

+2 阶：

| 项 | 计算 | 结果 |
|---|---|---|
| 伤害倍率 | `1 + 0.35×2` | 1.70 |
| 单发基础 | `700 × 1.70` | **1,190.0** |
| 穿透 | `80 × (1 + 0.20×2)` | **112.0** |

---

## 3. 第三步：穿透 → 有效护甲 → 护甲保留

**这是本作伤害体系的核心机制，也是最容易写错的一步。**

穿透**削弱目标护甲**，不是给自己增伤：

```
有效护甲 = 目标护甲 × (1 - 穿透/(穿透 + 60))          PIERCE_K = 60
护甲保留 = 1 - 有效护甲 / (有效护甲 + 100)
```

代入 480 护甲、112 穿透：

| 步 | 计算 | 结果 |
|---|---|---|
| 穿透削减比例 | `112 / (112 + 60)` | 0.6512 |
| 有效护甲 | `480 × (1 - 0.6512)` | **167.44** |
| 护甲保留 | `1 - 167.44/(167.44+100)` | **0.3739** |

**480 护甲被砍到 167**——穿透 112 把 BOSS 的护甲削掉了 65%。

对照一下同样条件下"穿透 0"会怎样：

| 穿透 | 有效护甲 | 护甲保留 | 相对收益 |
|---|---|---|---|
| 0 | 480.0 | 0.172 | 1.00x |
| 60 | 240.0 | 0.294 | 1.71x |
| **112** | **167.4** | **0.374** | **2.17x** |

**穿透从 0 到 112，伤害翻了一倍多。** 这就是"带穿刺武器"成为独立战术选择的原因，
也是穿透能作为第三条成长轴的依据。

### 3.1 一个被写错过的方向

初版设计稿把穿透写成"伤害再乘一个 `(1 - pierce/(pierce+40))` 的减伤"——
方向反了，那会让**穿透越高伤害越低**。见 `00-决策清单.md` A6。

## 4. 第四步：单发期望伤害

```
最终伤害 = 基础 × atkMul × levelDmgMul × 技能乘区 × 暴击期望 × 护甲保留 × 甲型克制
```

逐个算：

| 乘区 | 计算 | 结果 |
|---|---|---|
| 基础 | 见第 2 步 | 1,190.0 |
| `atkMul` | 见第 1 步 | 1.680 |
| `levelDmgMul` | 见第 1 步 | 2.00 |
| 技能乘区（致命标记） | `1 + (5/18)×(2.4-1)` | **1.3889** |
| 暴击期望 | `1 + (0.2401+0.15)×(1.5-1)` | **1.1950** |
| 护甲保留 | 见第 3 步 | 0.3739 |
| 甲型克制（穿刺 vs 重甲） | 矩阵查表 | 1.05 |

技能乘区是**期望值折算**：致命标记冷却 18 秒、持续 5 秒、倍率 2.4，
所以平均收益是 `1 + (5/18) × 1.4 = 1.3889`，不是 2.4。

相乘：

```
1190.0 × 1.680 × 2.00 × 1.3889 × 1.1950 × 0.3739 × 1.05
= 1190.0 × 4.6667 × 1.1950 × 0.3739 × 1.05
= 2,605.5
```

**单发 2,605.5 伤害。**

---

## 5. 第五步：攻速与换弹惩罚

**攻速必须作用在"频率"上，不能乘进单发伤害。**

```
攻击频率 = 武器射速 × hasteMul = 0.35 × 1.4752 = 0.5163 /s
单发周期 = 1 / 0.5163 = 1.9368 s
```

弹匣 5 发、换弹 2.5 秒：

```
弹匣周期 = 5 × 1.9368 = 9.684 s
换弹惩罚 = 9.684 / (9.684 + 2.5) = 0.7948
```

**为什么不能把 `hasteMul` 乘进单发伤害？**

如果乘进单发，`perHit × hasteMul`，然后换弹惩罚再按**未缩放**的射速算弹匣周期，
大弹匣武器的 DPS 会被系统性高估。攻击频率必须单独作为一个乘区。

薇拉的对 BOSS 单发周期是 1.94 秒——**一次换弹要吃 2.5 秒**，
占整个弹匣周期的 20.5%。这是狙击枪的隐性代价。

---

## 6. 第六步：单目标 DPS

```
DPS = 单发伤害 × 攻击频率 × 换弹惩罚 × AI 效率
    = 2605.5 × 0.5163 × 0.7948 × 0.75
    = 801.9
```

**薇拉单独一人对关底 BOSS 的 DPS 是 801.9。**

### 6.1 AI 效率系数 0.75

最后那个 `0.75` 不是修正项，是**前提**（`src/sim/combat.ts` 的 `AI_EFFICIENCY`）。
走位、切换目标、技能前摇、被击退都会损失输出。
所有 BOSS 血量都建立在这个值之上——**若原型实测发现队员空转更多，
必须下调这个值并重跑 BOSS 血量的反向校准**，不能只改一个。

### 6.2 换成时间读一遍

```
关底 BOSS 血量 94,000 ÷ 单角色 DPS 801.9 = 117.2 秒
```

**一个人打要将近两分钟，而目标击杀时间是 60 秒。**

这条除法就是"为什么必须是 5 人小队"的数值证明——
也解释了为什么"带谁都行"不成立：少一个输出位，关底就打不完。

实测全队 5 人击杀关底 BOSS 用了 **53.5 秒**（见 `02-数值表.md` §6.2）。

## 7. 反向验证：从实测倒推回公式

前面是"从属性推到 DPS"，这里反过来验一遍——**用模拟器的实测结果倒推，
看能不能回到同一组数字**。

| 阶段 | BOSS 血量 | 实测击杀 | 倒推小队 DPS | 公式解析式 DPS | 差 |
|---|---|---|---|---|---|
| 1 | 48,500 | 27.9s | 1,738 | 1,175 | +48% |
| 2 | 70,000 | 37.2s | 1,882 | 1,479 | +27% |
| 3 | 94,000 | 53.5s | 1,757 | 1,502 | +17% |

**实测 DPS 高于解析式，是预期内的**：解析式算的是"五个人的单体 DPS 相加"，
而模拟器里溢出伤害会顺延到下一个目标（`run-sim.ts` 的伤害结算循环），
加上近战武器的 `hitsPerAttack > 1` 在清场后的收益，实际输出必然更高。

**阶段 1 差得最多（+48%），因为那一场清场最彻底**——杂兵被移干净，
全队 5 人的溢出伤害全部灌在一个目标上，AOE 武器的收益最大化。

> 这条差值本身是有用的信号：**差值突然变小，说明 BOSS 战被杂兵稀释了**，
> 该去看 `BOSS_PHASE_SPAWN_MUL` 是不是配错了。

---

## 8. 这个演示验证了什么

| 检查项 | 结论 |
|---|---|
| 手算能复现代码输出 | ✓ 六步全部逐步对上 |
| 穿透是独立成长轴 | ✓ 0→112 让伤害翻 2.17 倍 |
| 攻速必须作用在频率上 | ✓ 否则换弹惩罚算错弹匣周期 |
| 等级收益走独立乘区 | ✓ 走力量只有 +13%，走独立乘区 +100% |
| 单角色打不穿关底 | ✓ 117.2s vs 目标 60s |
| 全队 5 人能打穿 | ✓ 实测 53.5s |

**没验证的**：这个 801.9 在真实战斗里手感对不对。
公式能证明"打得动"，不能证明"打得爽"——后者要原型试玩。
见 `02-数值表.md` §10 对模拟器边界的说明。
