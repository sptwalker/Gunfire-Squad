# 05 资产清单

> **美术风格已改为 Q 版体素（约 2.9 头身），见 §1.2 与 `00` A3。**
> 下文 §2.2 / §3.1 的 Rodin 提示词与"low-poly 人形"规矩是旧路线的记录，
> 角色与僵尸不再按它们生成；地形道具（§4）仍可用 Rodin 出参考后体素化。

> 本文解决一个问题：**哪些资产用 Rodin 生成，哪些必须买/外包。**
> 结论是明确的——Rodin 能覆盖静态资产的大部分，但有两类它做不了，
> 而这两类恰好是"做错了整个项目就瘸了"的两类。

---

## 1. 先说要紧的：Rodin 的边界

**Rodin 产出的是静态网格（static mesh），不带骨骼、不带动画。**

这不是 Rodin 的限制，是 AI 生成 3D 模型的通用现状。所以资产分成三类：

| 类别 | 能不能用 Rodin | 数量 | 说明 |
|---|---|---|---|
| **静态道具 / 地形** | ✅ 完全可以 | 大头 | 建筑、树木、岩石、油桶、掩体、道具 |
| **角色与僵尸本体** | ✅ 建模可以 | 21 个 | 但**动画要另做**（见下） |
| **动画** | ❌ 做不了 | — | 必须买带动画的资源包，或外包绑定 |

> 角色 12 + 僵尸 9 = **21 个**。（上一版写 20，是僵尸 7 + 角色 12 + BOSS 1 的旧算法。）

### 1.1 关键决策：用"带动画的资源包"而不是"给 Rodin 模型绑骨"

给 Rodin 生成的网格绑骨 + 做动画，成本远高于买一套现成的。
本作 21 个角色/僵尸的真实需求是：

```
每个单位需要： idle / move / attack / hit / death    5 个动作
21 个单位 × 5 动作 = 105 个动作
```

手工做 105 个动作不现实。（角色这一侧因为武器可换，实际降到 10 个，见 §2.3。）**推荐路径**：

| 单位 | 来源 |
|---|---|
| 12 名可玩角色 | 买带动画的 low-poly 人形包（Mixamo / Synty 风格），换材质区分 |
| BOSS ×3 | Rodin 生成模型 + 用现成人形骨架重定向 |
| 普通僵尸 ×9 | 买带动画的僵尸包，**或** Rodin 生成 + 重定向 |

**重定向（retargeting）是这里的关键技术**：把标准的 Mixamo 骨架
套到任意人形网格上，动作自动适配。这条路径让"Rodin 生成外观 + 现成骨架驱动"
成为可行方案——**外观可以完全定制，动作复用。**

> **已验证（M0 ✅）**：Rodin 网格能干净地绑到 Mixamo 骨架上，管线在 `proto/m0/tools/rig.py`，
> 实测数字见 `06-开发路线图.md` 的「M0 实测」。所以 12 名角色也可以走"Rodin 生成 + 绑骨"，
> 不必买角色包——**要买的只剩一套 Mixamo 骨架的动作包**（攻击 / hit / death，M0 用的是程序化占位）。

### 1.2 现行路线：Q 版体素 + 刚体部件（M0 后修订）

M0 证明了"Rodin 高精网格 + Mixamo 骨架"能跑，也证明了它**每个角色都要修一轮权重**：
袖子粘腰、腋下碎边、手指分不到指骨——修了三轮还剩碎边。21 个单位各来一遍不现实。

改成 Q 版体素后，问题从根上消失：

| | 旧：Rodin 高精网格 | 新：体素部件 |
|---|---|---|
| 网格来源 | Rodin 生成，一次 1 个，随机性大 | 按部件表拼格子（`tools/voxel.py`），改一格重跑一次 |
| 绑骨 | 权重投射 + 7 步修正 | **每块 100% 绑一根骨**，零混合——没有拉丝、粘连、撕裂 |
| 动作 | 世界空间重定向到 A-pose | Xbot 骨架只挪关节位置、不改骨骼朝向，**旋转关键帧原样可用** |
| 贴图 | 3 张 2048² → 压 1024² WebP | **没有贴图**，逐面顶点色 |
| 薇拉体积 | 559 KB / 7.8k 三角面 | **≈420 KB / 4.0k 三角面**（12 人 3.7k–5.0k） |
| 武器 | Rodin 生成 + 归一 | 同样拼格子（2 cm），11 把 4–10 KB |

**规格**（与 `voxel.py` 一致）：

- 格子 5 cm；头按 12 格画（脸 12×12 格，60 像素俯视下眼睛、刘海可读），出网格时绕脖子等比缩到 0.8 → 头高 0.48 m、身高 1.38 m，约 2.9 头身。缩放而不是重画 10 格，是因为 10 格的脸排不开眼睛 / 高光 / 腮红
- 部件：头（含头发、五官）/ 胸 / 臀腰 / 上臂 / 前臂 / 手 / 大腿 / 小腿 / 脚，各一根骨
- 同一部件内相邻格子的面剔掉，部件之间不剔（关节一弯不露洞）
- 挂点约定不变（§2.3）：`socket_hand_r / l`，武器原点在握把，运行时一个常量旋转
- 角色区分靠 §2.1 的**主色 + 轮廓件**（肩甲、兜帽、背罐……），都是加几块格子。
  12 人全在 `voxel.py` 的 `CHARS` 表里：肤 / 发 / 发型 / 上衣 / 裤 / 手套 / 体形（瘦 · 常 · 壮）+ 轮廓件列表，
  身体骨架与关节 12 人共用，差异只在表里

**Rodin 的新位置**：出参考图或粗模，给人看着拼部件；地形道具这种静态件可以直接 Remesh（Blocks）体素化。
僵尸同样走部件拼装——"九种轮廓两两可分"（§3）在格子里比在高精网格里更好控。

## 2. 角色（12 名）

俯视视角下，**角色只需要上半身的辨识度**——玩家看到的是一个 60 像素高的东西。
所以资产优先级是：**轮廓 > 主色 > 武器 > 细节**。

### 2.1 12 名角色的视觉区分方案

| 角色 | 定位 | 武器 | 主色 | 轮廓特征 |
|---|---|---|---|---|
| 铁壁·罗恩 | 坦克 | 大刀 | 钢灰 | 全队最宽的肩甲 + 盾 |
| 磐石·格温 | 坦克 | 长枪 | 深蓝 | 长枪竖持，高瘦 |
| 疾风·凯 | 近战 | 剑 | 亮红 | 轻装，无披风 |
| 断岳·铁牛 | 近战 | 大刀 | 橙褐 | 最壮，赤膊 |
| 鹰眼·薇拉 | 远程 | 狙击枪 | 墨绿 | 长枪管 + 风衣下摆 |
| 弹幕·杰特 | 远程 | 冲锋枪 | 亮黄 | 弹链斜跨 |
| 霜语·艾拉 | 控制 | 冷冻器 | 冰蓝 | 兜帽 + 背包罐 |
| 震地·博姆 | 控制 | 手雷 | 土黄 | 矮胖 + 腰挂雷 |
| 圣手·莉安 | 辅助 | 手枪 | 纯白 | 医疗包 + 十字 |
| 烈焰·萨满 | 辅助 | 喷火器 | 焦橙 | 双燃料罐后背 |
| 傀儡师·诺克斯 | 召唤 | 回旋镖 | 紫黑 | 长袍，无甲 |
| 蜂群·西芙 | 召唤 | 激光枪 | 青绿 | 无人机悬浮在肩 |

**这张表就是"12 个角色"的全部定义。** 只要主色和轮廓对得上，
玩家在俯视视角下就能一眼分辨——这比堆细节有效得多。

> 表里的"武器"列是**默认武器**，不是烘进角色网格的部件。见 §2.3。

### 2.3 武器：独立模型 + 手部挂点

军械库让武器可换、可共享（用户裁决 #1），局内还能捡临时武器（#2），
所以**武器不能画在角色身上**，必须是独立的 GLB，运行时挂到手上。

**角色网格一律空手生成**（§2.2 的模板；光写 `empty hands, no weapon` 压不住，M0 实测），
骨架上加两个挂点骨骼：

| 挂点 | 父骨骼 | 用途 |
|---|---|---|
| `socket_hand_r` | 右手 | 所有武器的主握点 |
| `socket_hand_l` | 左手 | 双手武器的副握点（IK 目标，不挂模型） |

**每把武器的原点就是握把**，朝向 +Z 为枪口/刃尖，这样挂上去不用逐把调偏移。
尺寸按角色身高 1.8 单位归一化，生成后在 `weapons.ts` 里只记一个 `gripOffset`（默认 0）。

14 把武器按**握持方式**分 6 类，动画按握持方式复用，不按武器：

| 握持 | 武器 | 攻击动画 |
|---|---|---|
| 单手近战 | 剑 | 单手挥砍 |
| 双手近战 | 大刀 · 长枪 | 双手横扫 / 前刺 |
| 单手射击 | 手枪 · 冲锋枪 | 单手射击 |
| 双手射击 | 突击步枪 · 狙击枪 · 喷火器 · 冷冻器 · 激光枪 | 抵肩射击 |
| 肩扛 | 火箭筒 | 肩扛发射 |
| 投掷 / 弓 | 手雷 · 回旋镖 · 弓箭 | 投掷 / 拉弓（弓共用投掷的上半身节奏） |

```
每个单位的动作：idle / move / hit / death      4 个，全员共享
攻击动作：      6 种握持 × 1                    6 个，按当前武器切换
```

所以换武器 = **换挂点上的模型 + 换攻击动画那一条**，其余动作不动。
§1.1 的"105 个动作"对角色而言变成 4 + 6 = **10 个**——武器可换反而让动作更少了，
因为角色不再各自绑死一套攻击。

**僵尸与 BOSS 不走这套**：它们的"武器"是身体，照旧烘进网格。

### 2.2 Rodin 提示词模板（角色）

**M0 验证过的模板**（Quad 模式，`quality_override: 8000`）：

```
3D figurine of <subject> in A-pose, both arms angled down and away from the body,
bare open hands with visible spread fingers, palms facing the thighs, hands completely empty.
<He/She> wears <clothing, 2-3 colors>, <hair>.
Unarmed civilian mannequin pose, stylized low-poly, full body, symmetric,
clean silhouette, flat lighting, plain background
```

**实际用上的一版（鹰眼·薇拉，第 8 次生成，图 + 文字）：**

先纯文字抽一张脸清楚的（v7），把它的正面渲染图**左半边镜像成左右对称**，作为参考图和下面的文字一起传：

```
young woman soldier in exactly this symmetric A-pose, both arms straight down and away from the body
with a clear gap to the torso and thighs, black gloved hands empty with fingers together,
fitted olive green jumpsuit with slim sleeves, belt, thigh holsters, black boots,
long auburn hair behind the shoulders, face fully visible, clean stylized face with clear eyes,
neutral expression, stylized low-poly game character, flat lighting
```

有参考图时 `soldier` 不会再塞枪进手里——姿态由图锁住了。

**M0 踩出来的规矩**（前 4 次生成失败的原因）：

| 规矩 | 违反的后果（实测） |
|---|---|
| **不写职业 / 武器词**（sniper、soldier、tactical） | 只要出现，Rodin 就会塞一把枪进手里——写了 `empty hands, no weapon` 也没用（v1、v2、v4 都拿着枪） |
| **把手写具体**：`bare open hands with visible spread fingers ... hands completely empty` + `unarmed civilian mannequin` | 只写 `empty hands` 压不住；描述手指形状才压得住 |
| **要 A-pose，别要 T-pose** | Rodin 几乎不出 T-pose，写了也是 A-pose 且左右不对称；管线（`rig.py` 第 2 步）会自动拟合手臂角度，所以 A-pose 反而最稳 |
| **服装不过膝，写 `hip-length fitted`** | 过膝长下摆跑步时被两条腿撕开，没有可用的权重解（v5 风衣实测）；v6 改短夹克后解决 |
| **手臂和衣身之间要有缝**：`clear gap to the torso and thighs`、`slim sleeves` | 袖子贴着衣身生成就是同一片网格，挥砍 / 死亡时袖子粘在腰上（v6 实测）；绑骨管线会切开手臂与腿臀之间的面，没缝就切出洞 |
| **手套 + 手指并拢**：`black gloved hands ... fingers together` | 张开的手指比 Xbot 的手长、会分到大腿权重；手指在管线里是刚体，并拢的手套最不容易穿帮 |
| **脸靠参考图**：先抽一张好脸，镜像成对称图再做图生模 | 纯文字的脸每次随机，左右还不对称 |
| **头发写 `tucked behind the ears, face fully visible`** | 头发盖脸时贴图会把发丝和脸糊在一起 |
| `plain background` | 生成带场景的图，抠模型要额外一轮 |
| `stylized low-poly` | 生成高细节模型，缩到 60 像素后是一团糊 |

> 角色的**职业感全部交给武器和配色**：武器挂在手上（§2.3），配色在 §2.1 的表里。
> 网格本身只是一个穿着对的衣服、空着手的人。

**武器提示词**：单独生成、`isolated weapon, side view, plain background`，
生成后跑 `proto/m0/tools/weapon.py` 把原点移到握把、+Z 朝前、按真实长度缩放。

## 3. 僵尸（9 种 + 1 变体）

**僵尸的资产优先级和角色不同**：它们同屏 300 只，且玩家不需要分辨个体。
所以优先级是：**行为可读性 > 外观多样性**。

| 僵尸 | 主色 | 轮廓特征 | 从轮廓就能读出的行为 |
|---|---|---|---|
| 普通 | 灰绿 | 标准人形 | 数量 |
| 高速 | 亮红 | 前倾，手臂后甩 | 冲刺 |
| 高防胖 | 暗黄 | 体积是普通僵尸 2 倍 | 阻挡 |
| 毒液 | 紫绿 | 腹部鼓胀发光 | 区域封锁 |
| 爆炸 | 橙红 | 身体有裂纹发光 | 逼迫走位 |
| 分裂 | 灰白 | 半透明，能看到内部有 3 个团块 | 清场惩罚 |
| 跳跃 | 深蓝 | 腿部细长，蹲伏姿态 | 无视地形 |
| **护盾**（新） | 银白 | **全场唯一带硬直角的人形**——正面一块弧形盾板 + 肩甲加宽 | 破防检查 |
| **喷吐**（新） | 黄褐 | 颈部前伸、背部一个鼓起的囊袋，**唯一不朝你走的人形** | 远程压制 |
| 分裂小 | 灰白 | 分裂僵尸的 40% 缩放 | （不需要独立资产——**复用分裂僵尸的网格做缩放**） |

**"轮廓唯一性"在这一轮变成硬约束了。** 旧版 7 种靠主色就能分开，
新版 9 种不行——其中两只（护盾 / 喷吐）的行为是"不靠近你"和"打不动"，
两者都不能靠颜色表达。所以 §7.1 那条"九种动词互不重叠"在资产层的对应物是：
**九种轮廓在 60 像素高时必须两两可分**（`护盾` 的直角盾板与
`喷吐` 的前伸颈部就是为此加的）。

**分裂小僵尸不单独生成资产**——它是分裂僵尸的 0.4 倍缩放。
省一次生成，也天然保证了视觉血缘。

### 3.1 Rodin 提示词模板（僵尸）

```
zombie <type>, top-down game character, full body, standing T-pose,
clean silhouette, readable at small scale,
<color> color scheme, <distinctive feature>,
low-poly stylized, game-ready asset, slightly hunched posture,
flat lighting, no shadows baked,
single isolated object, plain background

Negative: gore, blood splatter, realistic wounds, photorealistic
```

> **`Negative: gore` 是有意的。** 血腥过度的僵尸资产在多数分发渠道会被打回，
> 而"恐怖"不靠血堆——靠轮廓和颜色。俯视视角下也看不到细节。

## 4. 地形与道具（Rodin 的主场）

这一类是 Rodin 最划算的用途：**静态、无动画、数量多、俯视视角细节要求低。**

| 资产 | 数量 | 尺寸（格） | 主要场景 | 对应地形要素 |
|---|---|---|---|---|
| 建筑 | 6 种 | 4×4 ~ 12×12 | 城市废墟 / 军事禁区 | `building` 绝对阻挡 |
| 走廊隔断 | 3 种 | 1×N | 城市废墟 | `corridor` 强制单线 |
| 树木 | 4 种 | 1×1（**3 个尺寸靠缩放，不单独生成**） | 原始丛林 / 雪原冻土 | `openField` 的反面 |
| 岩石 | 3 种 | 1×1 ~ 2×2 | 荒漠废土 / 雪原冻土 | 掩体 |
| 掩体工事 | 3 种 | 1×2 / 2×2 | 军事禁区 | `coverDensity` 的实现物 |
| 栅栏/沙袋 | 3 种 | 1×N | 全部 | 同上 |
| **铁丝网**（本轮新增） | 1 种 | 1×N | 军事禁区 / 雪原冻土 | `wire` 挡人不挡弹，见 §4.3 |
| **木墙**（本轮新增） | 2 种 | 1×N / 2×N | 城市废墟 / 军事禁区 | `woodwall` 可炸开，见 §4.3 |
| 油桶 | 1 种 | 1×1 | 城市废墟 / 军事禁区 | `barrel` 可引爆 |
| 补给箱 | 2 种 | 1×1 | 全部 | `crate` 可破坏，掉落增益 |
| 增益道具 | 5 种 | 0.5×0.5 | 全部 | 需要一眼分辨（见 §4.1） |
| 毒洼 / 冰面 / 水洼 | 3 种 | 圆形 | 丛林 / 沼泽 / 雪原 | `pool` `ice` `water`——**全部贴地贴图，不用模型** |
| 残骸 | 1 种 | 1×1 | 全部 | 可破坏物被打掉后的共享碎石堆，见 §4.3 |

**树木的"3 个尺寸"不单独生成**——和分裂小僵尸一样，靠统一缩放。
生成 4 个模型比生成 12 个便宜，而且缩放出来的树天然共享同一套 LOD。

### 4.1 增益道具的视觉设计（唯一需要"抢眼"的道具）

5 种道具在战场上必须**在余光里就能分辨**：

| 道具 | 颜色 | 图标形状 |
|---|---|---|
| 防御盾 | 蓝 | 盾牌 |
| 加速 | 黄 | 双箭头 |
| 增伤 | 红 | 剑 |
| 加血 | 绿 | 十字 |
| 冷却缩减 | 紫 | 时钟 |

**颜色 + 形状双编码**，因为色盲玩家占比约 8%，只靠颜色会有一批人分不清。
道具本身用一个共享的底座模型（旋转发光的水晶），
上面挂不同颜色的**扁平图标贴片**——省 5 次生成，且图标永远面向相机。

### 4.3 三种可破坏障碍：**只做一套几何，新增 1 次生成**

本轮新增沙袋 / 铁丝网 / 木墙（`src/data/scenes.ts` 的 `OBSTACLES`）。
它们**复用已有的掩体几何**，改的是材质与破坏表现：

| 障碍 | 几何来源 | 打掉后 | 新增生成 |
|---|---|---|---|
| 沙袋 | 复用 `栅栏/沙袋` 已有模型 | 切残骸态（`residue: 'rubble'`） | **0** |
| 铁丝网 | 复用栅栏几何，换铁丝材质 | 直接隐藏（`residue: 'none'`） | **0** |
| 木墙 | 复用走廊隔断几何，换木板材质 | 切残骸态 | **0** |
| 残骸（共享） | 碎石堆，贴被打掉那个资产的材质 | — | **1** |

**"可破坏"要的不是新模型，是每个资产多一个残骸态**，
而残骸态可以全障碍共享一个网格。所以三种障碍的资产成本是
**一次材质 + 一次残骸生成**，不是三次。

这条与 `04-技术框架.md` §2.3 的位掩码是同一件事的两面：
**掩码里 `DESTRUCTIBLE` 那一位置上的对象，在美术上就是"可切到残骸态"的那个。**
判定侧只多了一个位，渲染侧只多了一次实例切换，两边都没有新增一类东西。

### 4.2 Rodin 提示词模板（道具/建筑）

```
low-poly stylized, game-ready,

top-down view readable,

```

## 5. 6 个场景的资产复用（材质着色契约）

**核心原则：6 个场景共用同一批网格，靠材质换色 + 2-3 个专属元素区分。**

这不是"省钱的妥协"，是本轮架构的直接要求。场景的区别在于
**它要什么阵容**（`08-关卡方案.md` §3），不在于它长什么样——
如果每个场景各生成一套僵尸，那么同一个"高速僵尸"在丛林和雪原会是两个模型，
玩家要学会认两遍，而学到的东西一模一样。

### 5.1 僵尸：同网格，换材质

**每只僵尸只有一个网格。** 场景变体通过 `MeshStandardMaterial` 的
`color` / `roughness` / `emissive` 三个参数偏移得到，不重新生成。

| 僵尸 | 基础主色 | 丛林（潮湿） | 雪原（冻伤） | 荒漠（干枯） | 沼泽（腐蚀） |
|---|---|---|---|---|---|
| 普通 | 灰绿 | 偏青 +8% 饱和 | 偏白 +20% 亮 | 偏黄 +5% 亮 | 偏褐 +10% 暗 |
| 高速 | 亮红 | 不变 | 不变 | 不变 | +15% 暗 |
| … | | | | | |

**"高速僵尸的红色在任何场景都不变"是刻意的。** 行为可读性（§3）高于场景氛围：
玩家在雪原里也必须一眼认出冲刺型。所以只有"数量型"僵尸参与换色，
**"行为型"僵尸保持全局同一主色**。

> 契约落在 `assets/materials/zombie_tint.json`，一格场景 × 一种僵尸 = 一组材质参数。
> 换场景 = 换一张 tint 表，不动网格。这条也让"场景配色"变成可调的，
> 而不是钉死在生成时。

### 5.2 地形：专属资产只有 2-3 个

| 场景 | 专属资产 | 复用 |
|---|---|---|
| 城市废墟 | 建筑 ×6、车辆残骸 | 通用道具、栅栏、油桶 |
| 原始丛林 | 草丛 ×3、干草堆 | 树木 ×4、毒洼贴图 |
| 沼泽疫地 | 枯树 ×2、水洼贴图 | 毒洼、岩石 |
| 荒漠废土 | 仙人掌 ×2 | 岩石 ×3、干草堆 |
| 雪原冻土 | 雪堆 ×2、冰面贴图 | 树木（覆雪材质）、岩石 |
| 军事禁区 | 掩体工事 ×3、铁丝网 | 建筑、栅栏/沙袋、油桶 |

每个场景只需 2-6 个专属资产，其余靠地表贴图 + 色调偏移。
6 个场景的总地形资产量因此压到 **30 个左右**，而不是 6 × 30。

> 这条对应 `00-决策清单.md` C5：场景改的是**挑战签名**，不是资产。
> 资产层面**同一套网格，换材质就是新场景。**

## 6. 特效（VFX）

俯视视角下特效的作用是**信息**，不是美观。所以只做"能传递状态"的那几种：

| 特效 | 传递的信息 | 实现 |
|---|---|---|
| 命中闪光 | 打中了 | 3 帧的白色叠加 |
| 暴击数字 | 这一下很重 | 飘字，橙色，1.5 倍字号 |
| 伤害数字 | 常规反馈 | 飘字，白色小字 |
| 中毒地面 | 这块地不能站 | 贴地贴图，带呼吸动画 |
| 冰冻 | 这只被控住了 | 单位套一层半透明蓝色壳 |
| 自爆预警 | 快跑 | 单位膨胀 + 红色闪烁 |
| 技能释放 | 谁放了大招 | 脚下光环扩散 |
| 治疗 | 谁在回血 | 单位向上的绿色粒子 |

**全部用 billboard 贴片或贴地贴图实现，不用粒子系统。**
300 只僵尸同屏时，粒子系统是第一个该砍的东西。

> **一个刻意的省略：不做血条飘字以外的"打击感"。**
> 屏幕震动、受击顿帧、镜头拉近——这些在原型阶段加，
> 现在做等于在不知道手感的情况下调手感。

## 7. 音频（占位，原型阶段再定）

本作的声音需求比一般射击游戏**低**——玩家不瞄准、不开枪。
真正需要声音的是**状态提示**：

| 音效 | 触发 | 优先级 |
|---|---|---|
| BOSS 登场 | 每 5 分钟 | 高 |
| 队员阵亡 | 死亡时 | 高 |
| 队员低血 | 血量 < 30% | 高 |
| 拾取增益 | 拾取时 | 中 |
| 关卡阶段切换 | 每 5 分钟 | 中 |
| 背景音乐 | 全程，按阶段分层 | 低 |

**攻击/命中的音效优先级最低**——300 只僵尸同屏时，枪声会变成噪音。
本作的声音设计目标不是"每一枪都响"，是"该听见的能听见"。

## 8. 资产生成的工作流

```
1. 批量生成      Rodin，按 §2.2 / §3.1 / §4.2 的模板，一次一个对象
2. 筛选          人工过一遍，挑轮廓清晰的（俯视视角下细节多的反而更差）
3. 压缩          gltf-transform：Draco + KTX2
4. 命名          <category>_<name>_<variant>.glb
5. 入库          assets/models/<category>/
```

### 8.1 命名规范（现在不定，后面会返工）

```
角色     char_ron.glb        char_vera.glb
僵尸     zomb_normal.glb     zomb_brute.glb
BOSS     boss_corrupted.glb  boss_chaos.glb
地形     prop_building_01.glb  prop_tree_pine_02.glb
道具     item_buff_shield.glb
武器     wpn_sniper.glb      wpn_greatsword.glb   （id 与 weapons.ts 的 WeaponId 一致）
```

**小写 + 下划线 + 数字后缀**，不用驼峰（跨平台大小写敏感问题）、不用空格。

### 8.2 一次性生成的预算估计

| 类别 | 数量 | 说明 |
|---|---|---|
| 角色 | 12 | 可玩角色，**空手生成**（§2.3） |
| 武器 | 14 | 独立模型，原点在握把；与 `WEAPONS` 一一对应 |
| 僵尸 | 9 | 分裂小复用缩放；**场景变体靠 §5.1 的材质契约，不额外生成** |
| BOSS | 3 | |
| 地形道具 | ~30 | 含 6 个场景的专属元素；树木的尺寸变体靠缩放；**沙袋/铁丝网/木墙复用已有几何，只换材质** |
| 增益道具 | 1 + 5 图标 | 共享底座 + 5 个图标贴片 |
| 残骸 | 1 | 共享碎石堆（§4.3），三种可破坏障碍切到同一个 |
| **合计** | **≈ 75 次生成** | 比上一版多 14 次（武器从角色身上拆出来，§2.3） |

按 Rodin 单次生成的成本，这是一次**可控的、一次性的**投入。
大头不在生成，在 §1.1 的**动画方案验证**——那才是原型阶段第一个要过的关。

> **注意 75 这个数不随关卡数增长。** 82 个子关卡用的还是这 75 个资产：
> 场景变体是材质，关卡变体是刷怪表（`src/data/scenes.ts`）。
> 这一条是"关卡由推导而来"在资产层的直接体现——**如果这里开始涨，
> 说明有人又开始手写关卡了。**
>
> 本轮新增三种障碍，资产只多了一次生成，靠的正是这条规矩：
> **障碍的差别写在 `OBSTACLES` 表里（4 个布尔位），不写在模型里。**
