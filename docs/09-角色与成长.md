## 1. 这一轮到底改了什么，为什么

上一轮最大的空缺：**技能与僵尸的关键机制只写在 `note` 文案里。**
"无视 40% 目标护甲"、"冻结 3 秒"、"召唤 2 只傀儡"——这些是散文。
后果是"这套阵容能不能破解这个挑战"这类问题**无法计算，只能靠嘴说**。

这一轮的改动只有一件事：**把机制变成字段。**

| 上一轮（文案） | 这一轮（字段） |
|---|---|
| "无视 40% 目标护甲" | `piercePct: 0.4` |
| "冻结 3 秒" | `freezeDuration: 3` |
| "召唤 2 只傀儡" | `summons: 2` |
| "全队对其伤害 +35%" | `vulnPct: 0.35` |
| "投掷 3 枚手雷" | `hitsPerCast: 3` |
| "链式激光额外跳 5 目标" | `chainTargets: 6` |
| "令目标减速" | `slowPct: 0.4` |

`Skill` 现在有 15 个机械字段（见 `characters.ts` 的 `Skill` 接口）。
**配平主乘区仍然只有三个**：`mul` / `duration` / `cooldown`——
`skillAvgMul()` 只读这三个，**其余字段一律不改变技能的等效 DPS**。

那它们改的是什么？**改的是这个技能能回答哪个维度。**

举一个例子说明这个区分有多必要：

> 薇拉的 `vulnPct: 0.35`（标记目标，全队增伤）和萨满的 `atkMul: 0.3`（光环全队加攻）
> 在配平上是**等价的**——都是约 1.3 倍的队伍伤害乘区。
> 但前者需要集火窗口、后者是常驻光环。
> 所以一个回答【围猎】（BOSS 与小怪同时压上时要能分火集火），
> 一个回答【开阔】（没有掩体、持续接战时要能一直打）。

**同等的数值，不同的形状。** 这就是"维度"和"数值"的分界线，
也是同样两个角色在不同关卡里价值完全不同的原因。

## 2. 答案标签：能力的形状，不是强度

`AnswerTag` 有 15 个标签，定义在 `scenes.ts`（维度知识），赋值在 `characters.ts`（角色知识）。
词表放 `scenes.ts` 是为了保持"`scenes.ts` 不引用任何角色数据"这条设计顺序。

| 标签 | 含义 | 回答的维度 |
|---|---|---|
| `aoeClear` | 范围清场：一次攻击覆盖多个目标 | 潮涌 |
| `singleTarget` | 单体点杀：不制造额外目标 | 分裂 · 精英护盾 |
| `sustainedDps` | 持续输出：不需要窗口，一直在打 | 开阔 · 围猎 · 潮涌 |
| `burst` | 爆发窗口：短时间把伤害集中砸出去 | 围猎 · 精英护盾 · 突进 · 分裂 |
| `pierce` | 直线穿透：无视部分护甲，且吃站位 | 重甲 · 卡口 |
| `explosive` | 爆炸灼烧：高额定值伤害，不吃护甲减免 | 重甲 · 卡口 · 潮涌 |
| `armorShred` | 破甲腐蚀：把目标护甲降下来给全队用 | 重甲 · 精英护盾 · 围猎 |
| `control` | 控制减速：限制移动 | 突进 · 自爆 · 分裂 |
| `taunt` | 堵口嘲讽：把敌人固定在一点 | 卡口 · 围猎 |
| `mitigate` | 减伤护盾：降低全队承伤 | 突进 · 毒区 · 远程压制 |
| `sustain` | 续航治疗 | 毒区 · 迟滞 |
| `ranged` | 远程射程：在威胁范围外解决战斗 | 远程压制 · 自爆 · 迟滞 · 毒区 |
| `mobility` | 机动突进：走位成本对你更低 | 迟滞 · 毒区 · 远程压制 · 开阔 · 自爆 |
| `summon` | 召唤物：用编制外的单位分摊 | 突进 · 远程压制 · 围猎 · 卡口 · 开阔 |
| `debuff` | 标记易伤：为全队制造集火窗口 | 围猎 · 精英护盾 |

**为什么不直接让角色写 `answers: DimensionId[]`。**
那样"两套阵容解同一个维度"这件事就不可见了。
`aoeClear` 和 `explosive` 都能回答潮涌，但前者怕分裂、后者怕贴身；
`pierce` 和 `armorShred` 都能回答重甲，但一个吃站位、一个吃集火。
**用形状做标签，多解性才是数据，而不是文档里的一句声称。**

注意几个标签刻意覆盖了看起来不相关的维度，这是设计意图：

- `ranged` 一个人同时回答**四件事**：够得着远程、点得掉自爆、不用踩毒、不用走位。
  所以一个狙击手在四种完全不同的关卡里都有位置——**这是"通用性"的正确形态**，
  它不是"数值高所以哪都能上"，而是"这一个形状恰好对上四种压力"。
- `mobility` 同理，覆盖五个维度。**迟滞地形的答案不是"走得快"，是"走位对你便宜"**，
  所以躲自爆、离毒区、脱迟滞、在开阔地重新站位，都是同一个能力的四种用法。

## 3. 12 名角色（技能层）

一级属性总和全部为 100 点（哨兵 §1 机械校验），角色差异靠**分配方式**体现。
下面只列技能层——**属性与武器一行未改**。

### 坦克

| | 铁壁·罗恩 | 磐石·格温 |
|---|---|---|
| 武器 | 巨剑 | 长枪 |
| 定位 | 坦克 | 坦克 |
| 技能 | **磐石壁垒** 20s/6s ×1.4 | **穿刺阵列** 16s/4s ×2.2 |
| 机械字段 | `teamDefMul: 0.5` | `piercePct: 0.4` |
| 答案 | `taunt` `mitigate` `aoeClear` | `pierce` `aoeClear` |
| 覆盖维度 | 7 | **4（全游戏最少）** |

罗恩是"让队伍扛住"的形状，格温是"打穿一条线"的形状。
**格温只覆盖 4 个维度，是有意为之**——她是全游戏最专精的角色，
在重甲/卡口关卡里是硬解，在别的场景里就是普通的坦克。
阵容深度需要这种极端角色：如果每个角色都覆盖 7-8 个维度，
选谁就都差不多了（这正是 §6 那个坏消息的根源）。

### 近战输出

| | 疾风·凯 | 断岳·铁牛 |
|---|---|---|
| 武器 | 长剑 | 巨剑 |
| 技能 | **疾风连斩** 12s/3s ×2.6 | **裂地斩** 14s/2s ×3.0 |
| 机械字段 | `rateMul: 2.0` `critAdd: 0.3` `moveMul: 1.4` | `knockback: 2` `armorShredPct: 0.25` |
| 答案 | `burst` `singleTarget` `mobility` | `aoeClear` `control` `armorShred` |
| 覆盖维度 | **10（并列最多）** | 8 |

凯是全游戏覆盖最广的角色，因为他一个人回答了"爆发窗口"和"走位成本"这两件
分属不同族的事。**这让他成为最万金油的第五人**——也是配平上最需要盯的角色，
万金油如果数值还高，别人就没位置了。所以他的武器是长剑（低基础伤害）。

### 远程输出

| | 鹰眼·薇拉 | 弹幕·杰特 |
|---|---|---|
| 武器 | 狙击枪 | 冲锋枪 |
| 技能 | **致命标记** 18s/5s ×2.4 | **弹幕压制** 15s/5s ×1.9 |
| 机械字段 | `vulnPct: 0.35` | `reloadZero` `rateMul: 1.4` |
| 答案 | `debuff` `ranged` `singleTarget` `burst` | `sustainedDps` `control` `burst` |
| 覆盖维度 | 8 | 7 |

薇拉是**唯一自带 `ranged` 的角色**——她是远程压制的正解。
杰特的 `reloadZero` 让他在"潮涌"里能一直打，是 `sustainedDps` 的代表。

### 控制

| | 霜语·艾拉 | 震地·博姆 |
|---|---|---|
| 武器 | 冷冻枪 | 榴弹 |
| 技能 | **绝对零度** 22s/3s ×1.5 | **连环爆破** 18s/4s ×2.8 |
| 机械字段 | `freezeDuration: 3` `vulnPct: 0.5` `teamDefMul: 0` | `knockback: 1.5` `slowPct: 0.4` `hitsPerCast: 3` |
| 答案 | `control` `aoeClear` `debuff` | `explosive` `aoeClear` `control` |
| 覆盖维度 | 6 | 8 |

艾拉的 `teamDefMul: 0` 是全场**完全免伤** 3 秒，配合 `vulnPct: 0.5`
——这 3 秒是明确告诉玩家的"现在集火"。她的形状是**时间窗口**。
博姆是**空间窗口**：击退 + 减速把敌人推开，制造距离。
两个人都在"控制"，但一个控制时间、一个控制空间。

### 辅助

| | 圣手·莉安 | 烈焰·萨满 |
|---|---|---|
| 武器 | 手枪 | 火焰喷射器 |
| 技能 | **生命涌流** 20s/4s ×1.0 | **战意图腾** 24s/8s ×1.7 |
| 机械字段 | `healPerSec: 0.06` | `atkMul: 0.3` `rateMul: 1.2` `burnPctPerSec: 0.01` |
| 答案 | `sustain` `mitigate` `singleTarget` | `explosive` `sustainedDps` `debuff` |
| 覆盖维度 | 6 | 7 |

莉安是**全游戏唯一有 `sustain` 的角色**（另一个来源是罗恩的专精顶层），
而 `sustain` 是迟滞与毒区两个维度的答案之一。**她是消耗战的钥匙。**
萨满的 `burnPctPerSec` 是**按目标最大生命百分比**的灼烧——
百分比伤害对高血量单位收益更高，所以他在重甲关卡里有超线性价值。

### 召唤

| | 傀儡师·诺克斯 | 蜂群·西芙 |
|---|---|---|
| 武器 | 回旋镖 | 激光 |
| 技能 | **骸骨傀儡** 26s/10s ×1.8 | **纳米蜂群** 16s/6s ×2.1 |
| 机械字段 | `summons: 2` | `chainTargets: 6` `armorShredPct: 0.2` |
| 答案 | `summon` `singleTarget` `aoeClear` | `aoeClear` `armorShred` `sustainedDps` `summon` |

诺克斯的 `summons: 2` 是**编制外的单位**——这是唯一能同时回答
"堵一个方向"（卡口）和"顶住突进"的能力。西芙是唯一同时有
`aoeClear` + `armorShred` + `sustainedDps` 的角色，清场与破甲一身，
**代价是她的武器基础伤害最低**。

> 只看基础 `answers` 会得到更小的数——两条路径曾经分叉过，
> 现在哨兵里只有 `dimCoverage()` 一个定义，见该函数的注释。

### 4.1 稀有维度是真正的约束

上表里 `定位` 那一列才是有信息量的：

| 维度 | 定位数 | 说明 |
|---|---|---|
| **迟滞** | **4** | 只有机动力与治疗能答——**全游戏最窄的维度** |
| **重甲** | 5 | 只有穿透/爆炸/削甲类，与"堆攻击力"完全隔离 |
| **开阔** | 4 | 需要持续输出或编制外单位 |
| **毒区** | 4 | 治疗、射程与机动 |
| 其余 8 个 | 5-6 | 覆盖宽松 |

**迟滞是最窄的维度**，而且它的 4 名回答者（罗恩、凯、薇拉、莉安）与毒区**完全重合**：

```
迟滞 = 毒区 = { 罗恩, 凯, 薇拉, 莉安 }
```

这意味着**任何要打沼泽疫地或雪原冻土的阵容，都必须在这 4 人里选人**——
而这两个场景的维度构成不同（一个是迟滞+毒区+远程压制，一个是迟滞+围猎+精英护盾），
却指望同一批角色。**这是"阵容选择有后果"目前唯一真正站得住的实例，
同时也是它的上限：整个 12 维体系只收敛出这一条约束**（见 §7.2）。

## 5. 专精树：唯一的局外强化（B4/B5 修订）

### 5.1 硬约束：专精只能改公式的输入，不能新增乘区

`SpecEffect` 是一个刻意设计过的联合类型，里面**没有**"新增伤害乘区"这个变体：

```ts
export type SpecEffect =
  | { kind: 'attr'; attr: keyof Primary; amount: number }
  | { kind: 'weaponTier'; amount: number }
  | { kind: 'skill'; field: 'cooldown' | 'duration' | 'mul' | 'healPerSec' | 'teamDefMul'; amount: number; mode: 'add' | 'mul' }
  | { kind: 'ai'; field: 'aggroRange' | 'leashRange' | 'engageDistanceMul' | 'retreatHpPct'; amount: number }
  | { kind: 'answer'; add: AnswerTag }
  | { kind: 'revive'; charges: number };
```

原因是一条已经付过代价的约束：`core.computeDamage` 与 `sim.computeDamage` 之间
有一个 **324 用例、1e-6 容差的对账测试**，前提是两者签名一致。
一旦专精能插乘区，`core` 就要多接一个参数，对账测试立刻失效。

**这条约束由编译器执行，不是靠注释提醒。**

### 5.2 节点效果分五类，其中一类最重要

| 类型 | 作用 | 是否改变"这个角色能进哪些阵容" |
|---|---|---|
| `attr` | 增减一级属性 | ✗ |
| `weaponTier` | 解锁更高武器阶 | ✗ |
| `skill` | 改技能参数 | ✗ |
| `ai` | 改索敌/走位参数 | ✗ |
| **`answer`** | **新增维度答案** | **✓ 唯一一类** |

**只有 `answer` 类节点改变阵容可行性。** 这正是用户要的"build 小队不同维度战斗能力"——
其余四类都是数值强化，只有这一类是**能力拼图**。

所以设计规则是：**每个角色的专精顶层节点，原则上应该是 `answer` 类。**
下面是实际数据，以及它暴露的问题。

### 5.3 12 棵专精树

每个角色 3 个节点，成本 1/2/3，按顺序解锁。顶层（cost 3）是决定性的那个。

| 角色 | 顶层节点 | 效果 | 新增答案 | 覆盖维度 |
|---|---|---|---|---|
| 铁壁·罗恩 | 不屈壁垒 | `answer: sustain` | ✓ | 7 → 7 |
| 磐石·格温 | 铁壁枪阵 | `answer: taunt` | ✓ | 4 → 4 |
| 疾风·凯 | 疾风不息 | `answer: sustainedDps` | ✓ | 10 → 10 |
| 断岳·铁牛 | 山崩 | `answer: explosive` | ✓ | 8 → 8 |
| 鹰眼·薇拉 | 破盾弹 | `skill: mul ×1.5` | ✗ | 8 → 8 |
| 弹幕·杰特 | 火网 | `skill: mul ×1.6` | ✗ | 7 → 7 |
| 霜语·艾拉 | 冰封核心 | `skill: cooldown −6` | ✗ | 6 → 6 |
| 震地·博姆 | 破片装药 | `answer: armorShred` | ✓ | 8 → 8 |
| 圣手·莉安 | 战地复活 | `revive: 1` | ✗（见 §5.5） | 6 → 6 |
| 烈焰·萨满 | 熔甲 | `answer: singleTarget` | ✓ | 7 → 7 |
| 傀儡师·诺克斯 | 亡者军团 | `skill: duration +10` | ✗ | 8 → 8 |
| 蜂群·西芙 | 蜂群缠附 | `answer: control` | ✓ | 10 → 10 |

**7 / 12 个顶层节点是 `answer` 类**，5 个是数值类。

### 5.4 一个必须承认的问题：5 个顶层节点是纯数值

薇拉、杰特、艾拉、诺克斯的顶层节点只加数值，不加答案。
按 §5.2 自己定的规则，**这 5 个是不符合设计意图的**。

保留它们的原因是：薇拉的 `×1.5` 让她成为唯一能一枪打穿护盾的手段，
诺克斯的 `+10s` 把傀儡从"技能"变成"常驻兵力"——
这两个是有形状的强化，只是**形状没有落在 `ANSWER_DIMS` 的现有词表里**。

真正的修法有两条，都不在本轮范围内：

1. **扩词表**：加 `siege`（攻坚：单发高额，专门对护盾与高血量）之类的标签，
   把薇拉的顶层从"倍率"改写成"答案"。
2. **改节点**：让这 5 个顶层也产出 `answer`，接受角色定位的漂移。

**本轮选择先如实记录，不假装已解决。** 这是 `08-关卡方案.md` §8 的遗留项之一。

### 5.5 C2 落地：全游戏唯一的复活

决策 C2 明确"不做统一的队员复活机制"。所以**没有任何通用复活**：
队员阵亡就是阵亡，本局不再回来。

唯一例外是**莉安的顶层节点「战地复活」**（`{ kind: 'revive', charges: 1 }`）：
每局一次，把最近阵亡的队员以 50% 生命拉回战场。

**为什么放在辅助位的专精顶层而不是做成通用机制**：
通用复活会让"阵亡"这个状态失去意义——所有人都能回来，等于没有阵亡。
做成一个角色的一条专精，它就变成了**阵容决策**：你要不要为了这一条，
占掉一个位置、并且把 3 点专精全押在莉安身上？

## 6. 成长线（B4/B5 修订）

### 6.1 局外成长只有两样

按决策 C3，**武器不做局外养成**。所以局外的长期成长只剩：

```
通关 → 解锁新的英雄与武器【种类】
     → 积累专精点 → 点开专精节点
```

**没有数值刷取。** 一个角色的强度上限，在同一关卡内是固定的
（等级 1→5、武器阶 0→2 全靠局内积分，见 `run.ts` 的 `LEVEL_COST`）。

这样设计的原因是它直接服务于"不堆数值"那条要求：
**如果玩家能靠刷局外数值过掉一个维度，那这个维度就退化成数值了。**
卡住玩家的时候，他唯一能做的事是**换阵容**——因为没有任何数值可以刷。

### 6.2 专精点从哪来

倾向于**通关新关卡给专精点，而不是可刷取的货币**。
理由同上：可刷取的货币等于可刷取的数值，会重新打开"堆数值"这条路。

具体曲线属于 `06-开发路线图.md` M3 的范围，本轮不定。

### 6.3 局内成长：答案组合也能变

C3 的读法是：**局内拾取可以临时给队员换上未解锁的武器。**
这让一次 run 之内的答案组合也能变化——中途捡到一把榴弹枪，就临时获得了
`explosive` 这个答案，可以应对突然出现的重甲波。

这条是"局内 build"与"局外 build"的接缝。**如果 C3 原意不是这个，需要纠正。**

## 7. 多阵容的可验证性——诚实的结论

这是用户明确要求的一条：**"每种挑战，玩家不止有单一的阵容方案，而是可以有
非常多种不同的组合阵容方案。"** 这一条不能只靠声称，所以哨兵做了机械枚举。

### 7.1 哨兵 §10 做了什么

枚举全部 C(12,5) = 792 套阵容，对每一关数"有多少套阵容能覆盖该关的全部活跃维度"。

```
阵容总数                                792
能覆盖全部 12 个维度的阵容              693 套（占 87.5%）
全 82 关里门槛最高的一关                736 套可行（占 92.9%）
```

### 7.2 这个数字证明的事情比它听起来弱得多

**覆盖门槛几乎不筛人。** 最紧的一关也放行 92.9% 的阵容。
原因是结构性的：5 名队员、每人平均能回答 **7.4 个**维度，并集自然铺满全集。

**所以"能不能进"这件事基本是免费的。二分覆盖数不能证明"阵容选择有后果"。**

而且 82 关里**有 38 关并列同一个门槛**（736 套）。按维度构成归并只有 7 组——
门槛完全由「最稀有的那个维度」单方面决定：

```
含 sluggish  → 736 套，不管另外两个维度是什么
含 poison    → 736 套，同理
其余         → 760-771 套
```

**换句话说：12 个维度里，只有 2 个（迟滞、毒区）在覆盖层面真正约束阵容——
而且约束的是同一批人（§4.1）。** 所以两条约束实际只有一条。
其余 10 个维度"答不答得出来"几乎不构成门槛。这是本轮设计的下限，
必须说清楚，而不是拿 792 这个数字当背书。

### 7.3 真正该量的是什么，为什么现在量不了

**决定阵容区分度的不是"能不能答"，是"答得好不好"——
同一维度下不同答案的效率差。**

具体地说：用穿透枪阵解潮涌，和用范围清场解潮涌，清怪速率差多少？
如果差 5%，那两个答案其实是一个；如果差 40%，阵容选择才有后果。

要量这个，必须把**维度折进刷怪与承伤模型**——让"开阔"真的改变刷怪方位分布、
让"迟滞"真的改变走位时间、让"潮涌"真的改变同时接战数。
这需要 M2 参数化 `run-sim.ts`（当前有 10 处硬编码的 3 阶段假设）。

**当前模拟器结构上做不到，所以本轮不声称阵容已经有多样性。**
只声称一件事：**维度没有死胡同**——每个维度都有 ≥3 种答案形状、
≥2 个不同定位可回答，不存在"没有任何角色能应付的维度"。这是可玩性下限。

### 7.4 剩下三个能立刻做的方向

不在本轮范围，但记在这里避免遗忘：

1. **加稀有维度**：目前只有 2 个维度真正筛选阵容。把更多维度的答案面收窄
   （比如让"开阔"也只有 3 个定位能答），阵容选择才会真正有后果。
2. **把"答案数量"换成"答案效率"**：给每个 `AnswerTag` 对每个维度的
   效率系数，哨兵直接算加权值而不是布尔覆盖。这不需要动模拟器，
   只需要一张 15×12 系数表——**这是当前架构下最便宜的下一步。**
3. **M2 原型**：让维度真正影响刷怪与走位，用实测数据回填第 2 步的系数表。
