#1.0 六属性的分工边界（改之前先读这一条）

一级属性 提供 拿走
力量 STR 近战伤害乘区、近战击退力 —
敏捷 AGI 攻速、移速、远程击退力 暴击率

智力 INT 能量、技能强度、冷却缩减 —

体质 CON 生命上限 —

规则：每个属性只管自己那一列，不许跨列。 旧版"敏捷给暴击""韧性给血" 就是跨列的典型，结果是堆敏捷的角色同时拿到攻速和暴击、堆韧性的同时拿到血和甲—— 两个属性各顶两条线，另外两个属性没有独立理由被堆。

拆成"四条攻击线、三条生存线互不重叠"之后，"这角色该堆什么"才有唯一答案。 这条规则与 §11 的控制对抗轴是同一条思路：每个系统里，每一项都要有独立的对抗面。

#1.0.1 两层"地板"：抗暴击上限与控制抗性

ANTI_CRIT_CAP = 0.5 与 §11 的"减速不设对抗属性"是同一条设计原则的两个实例：

控制与反制体系必须每层都留地板，否则整条成长轴会被一次堆满而作废。
  • 抗暴击封顶 0.5：堆韧性能砍掉一半暴击收益，但永远砍不干净—— 留一半地板，幸运流才有活路。
  • 减速不设任何对抗属性：它是全游戏唯一不受抗性影响的控制手段， 也就是第 13 维度上永远关不上的一格（见 §11.4）。

#1.1 两条容易算错的地方

A. 敏捷的攻速必须作用在"频率"上，不能乘进单发伤害。

攻击频率 = 武器射速 × (1 + 敏捷×0.01)

若把攻速乘区乘进单发伤害，换弹惩罚会按错误的弹匣周期计算， 大弹匣武器的 DPS 会被系统性高估。

B. 等级伤害走独立乘区，不去缩放力量。

atkMul = 1 + 力量×0.02 带一个 +1 基数。若让等级缩放力量， 力量 34→45 只会让乘区从 1.68 到 1.90（+13%），完全跟不上关卡缩放。 拆成 levelDmgMul 之后"每级 +25%"才是实数，玩家算得清。

#2. 伤害公式（damage.ts）

最终伤害 = 基础 × atkMul × levelDmgMul × 技能乘区 × 暴击期望
         × 护甲保留 × 甲型克制

有效护甲  = 目标护甲 × (1 - 穿透/(穿透+60))        PIERCE_K = 60
护甲保留  = 1 - 有效护甲/(有效护甲+100)
暴击期望  = 1 + max(0, 暴击率 - 目标抗暴击) × (暴击伤害 - 1)
技能乘区  = 1 + (持续时间/冷却) × (倍率 - 1)

抗暴击扣的是暴击率，不是伤害。 这样"抗暴击"与"暴击率"共用一把 0-1 的尺子， 而不是又多出一个伤害乘区——伤害乘区已经够多了。扣到负数时归零，不倒扣成负暴击。 （damage.ts 的 expectedDamage；computeDamage 拿到的是"这一下暴没暴"的既成事实，不看抗暴击。）

#2.1 穿透的实际收益（这是设计的关键卖点）

穿透削弱目标护甲，所以对高护甲目标的收益是陡峭的：

目标护甲 穿透 0 保留 穿透 30 保留 穿透 60 保留 穿透 80 保留 80 / 0
30（普通僵尸） 0.77 0.83 0.87 0.89 1.15×
220（胖僵尸） 0.31 0.41 0.48 0.52 1.65×
480（关底 BOSS） 0.17 0.24 0.29 0.33 1.90×

打关底 BOSS 时，穿透 80 的伤害是穿透 0 的 1.90 倍，对普通僵尸只有 1.15 倍。 收益随目标护甲单调变陡——这就是"带穿刺武器"成为有意义战术选择的原因， 也是"穿透"能作为独立于攻击力的第三条成长轴的原因。

漂移修正：旧表写的是 BOSS 列 0.26 / 0.35 / 0.41、结论"2.4 倍"。 那组数字对应的是一个比现行 PIERCE_K = 60 更小的常数（约 34）， 表是改常数之前算的，改完没有重算。按本节自己写的公式，正确值是上表。 结论方向不变（穿透对重甲收益更陡），但幅度被高估了约 25%。

#3.3 一次真实的配平修正（留作教训）

初版狙击枪射速 0.45、冲锋枪单发 38 且暴击 -5%。结果：

修前 DPS 修后 DPS
鹰眼·薇拉（狙击） 596 489
弹幕·杰特（冲锋枪） 236 330

修前的问题：狙击枪在射程（60>20）、穿透（80>10）、单发（700>38）、 换弹惩罚、暴击加成上全面碾压冲锋枪，DPS 还是它的 2.5 倍。 "选武器"变成了"选最强的武器"，阵容深度直接消失。

修后的取舍：狙击枪赢在单发爆发（对高护甲 BOSS 的关键）， 输在持续输出（打小怪海乏力）；冲锋枪反之。 远程 DPS 定位内部的极差从 2.53x 收敛到 1.48x。

原则：任何一把武器都不应该在所有维度上都赢。 如果出现了，说明某个维度的代价没有被算进去。

  1. 稳固段定在 32-90，是咬住英雄击退力跨度定的（英雄实测跨度 7.7 ~ 96.8）。 第一版照抄英雄端 TGH×1.0 的量纲定在 8-20，结果是任何一把像样的武器 对任何一只非霸体僵尸都恒为 0.84——这一维根本没有咬合，玩家感觉不到稳固存在。 数值轴要能被感觉到，两端的尺度必须先对齐。
  2. 霸体只免疫位移（击退 + 击倒），刻意不免疫冻结/嘲讽/减速—— 那三类各有独立的对抗属性。做成"免一切控制"是最省事也最糟的写法： 它会让整个控制流一次性作废，玩家学到的教训就变成"别带控制"。
  3. 僵尸也反推英雄（knock 这一列）。只给英雄加稳固、僵尸这边没有对应值， 那条属性就永远只在自己人之间比大小，没有战场意义。 近战偏击倒（短暂失去行动，不位移），远程偏击退（位移，打乱阵型）。

推导链条是反向的：

#7.2.1 金钱买到的是新答案，不是新数字

这是本轮最要紧的一条边界，写在 progression.ts 的文件头：

买【种类】 → 给的是新答案：新武器意味着新的维度解（新的穿透/控制/清场手段）
买【阶/等级/属性】 → 给的是新数字：同一套答案打得更疼

#11. 控制对抗矩阵

这一节是本轮新增的第二大块。 上一轮的控制手段（击退、冻结、嘲讽）只存在于 技能文案里，僵尸这边没有任何对应的抗性字段——于是"这套阵容能不能破解这个挑战" 这类问题无法计算，只能靠嘴说。本轮把它做成一张两端对撞的判定表。

一条判定，两端对撞，形状直接复用已有的 PIERCE_K = 60 饱和曲线，不引入新数学形式：

位移命中率 = clamp(0.85 × atk² / (atk² + stab²), 0, 0.85)
                atk  = 武器击退 × 力量/敏捷乘区
                stab = 目标稳固
概念 在哪 含义
击退力 武器 knockback × 近战 1+STR×0.012 / 远程 1+AGI×0.012 攻方
稳固 英雄：TGH×1.0 派生；僵尸：表值 stab 守方
霸体 僵尸表布尔 superArmor 只免位移（击退 + 击倒）。冻结/嘲讽/减速照常生效
抗冻 僵尸表 freezeRes 抵冻结的概率与削减冻结时长
狡诈 僵尸表 cunning 抵嘲讽

上限 KNOCK_CAP = 0.85，不是 1.0 —— 理由与抗暴击上限同源： 任何一条控制的顶端都要留一层地板，否则"这套控制对这只怪无效"会变成 "这套控制对所有怪都无效"，玩家学到的教训是别带控制，而不是换一种控制。

减速是全游戏唯一不设对抗属性的控制，这是故意的，见 §1.0.1。 它也是第 13 维度上永远关不上的那一格。
