# Gunfire Squad

俯视 3D 小队生存射击，Q 版体素美术（2.5 头身）。玩家只控制队长移动，另外 4 名队员自动跟随、自动索敌、自动开火与放技能。

游戏结构是 **世界地图 → 6 个场景 → 82 个子关卡**。每个子关卡 = 一次 15 分钟的 run：
在 256×256 格的战场里抗住三波僵尸（每波 5 分钟），每波末尾打一个 BOSS。
关与关之间变难靠的不是数值，是**构成**——每个子关卡提出一种新的挑战维度（压力来源），
卡住时该换阵容，不是回去刷数值。

局内**零购买**：等级与武器阶按存活时长自动成长，玩家的手只用来打。
局外三条线各卖各的，产出条件互不重叠——**金钱买装备本身**（买断、会用这一类武器的角色共享），
**技能点**来自星级（每颗新星 1 点，三星封顶），**荣誉值 → 军衔**来自局内随机任务。
军衔效果被编译器限制在 `skill` / `ai` / `tactic`（地雷、工事、炮火等战术动作）上，一条 `attr` 都不给。
世界地图是 6 条并列的区域线，跨关只继承军衔、技能与军械库。

**当前阶段：创意阶段规划完成，数值配平已闭环。尚未编写游戏代码。**

## 跑数值哨兵

```bash
npm run sim          # = node src/sim/balance-check.ts
```

Node 24 原生支持 TypeScript 类型剥离，不需要 tsx / ts-node。输出十二个部分的实测表：
角色一级属性预算（六属性 / 合计恰为 150） / 单角色基准（含四属性→六属性的偏离闸门） /
BOSS DPS 锚点 / BOSS 血量反向校准 / 生存压力 / 15 分钟全程模拟 / 承伤现实检查 /
多阵容 × 多种子鲁棒性 / 挑战维度覆盖矩阵 / 阵容多样性枚举 / 控制对抗矩阵 /
军衔与技能点的时间成本。

原始输出留档在 `docs/.balance-raw.txt`，用于后续 diff。

## 数值的两条入口

- **改数字** → `src/data/*.ts`（`attributes` / `damage` / `weapons` / `zombies` / `characters` / `run` / `scenes` / `progression`）
- **改图表** → `src/sim/numbers-doc.ts`，然后 `node src/sim/numbers-doc.ts > docs/02-数值表.html`；**改哨兵** → `src/sim/balance-check.ts`，`npm run sim`

文档里的数字**全部**从模拟器导出，不手填——手填的表会和代码漂移，这一条已经被坑过一次。
82 个子关卡的刷怪表同理：没有手写的关卡配置，全部由 `scenes.ts` 的 `expandScene()` 推导。

## 模拟器能回答什么

**能**：清怪速率够不够、BOSS 血量锚点对不对、阵容之间有没有区分度、各乘区有没有写错、
**每个挑战维度有没有死胡同**（每个维度 ≥3 种答案形状、≥2 个定位可答）。

**不能**：会不会死人、难度手感对不对、走位有没有意义。原因是它的三个简化
（地图抽象成一维距离 / 索敌是单点最近目标 / 队员完全不走位）叠起来抹掉了整个生存维度——
详见 `docs/02-数值表.html` §10，那是全文最重要的一节。

还有一条**被证伪过的期待**：模拟器能证明"每个维度都有多种解"，
但**不能**证明"很多种组合真的可行"——13 个维度实际只收敛出 1 条真约束。
本轮新增的第 13 维「控制抗性」**扩大了这个反例而不是缩小它**：它的回答面是全员 12 人，
在覆盖层面约束力为 0（它的真约束在判定层，见 `docs/08` §7.4）。
这条边界如实记在 `docs/00-决策清单.html` D0，不拿阵容枚举的数字当背书。

难度必须靠真人原型试玩验证，不是靠这张表。
