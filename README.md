# Gunfire Squad

俯视 3D 小队生存射击。玩家只控制队长移动，另外 4 名队员自动跟随、自动索敌、自动开火与放技能。

游戏结构是 **世界地图 → 6 个场景 → 82 个子关卡**。每个子关卡 = 一次 15 分钟的 run：
在 256×256 格的战场里抗住三波僵尸（每波 5 分钟），每波末尾打一个 BOSS。
关与关之间变难靠的不是数值，是**构成**——每个子关卡提出一种新的挑战维度（压力来源），
卡住时该换阵容，不是回去刷数值。武器没有局外养成。

**当前阶段：创意阶段规划完成，数值配平已闭环。尚未编写游戏代码。**

## 跑数值哨兵

```bash
npm run sim          # = node src/sim/balance-check.ts
```

Node 24 原生支持 TypeScript 类型剥离，不需要 tsx / ts-node。输出十个部分的实测表：
角色一级属性预算 / 单角色基准 / BOSS DPS 锚点 / BOSS 血量反向校准 /
生存压力 / 15 分钟全程模拟 / 承伤现实检查 / 多阵容 × 多种子鲁棒性 /
挑战维度覆盖矩阵 / 阵容多样性枚举。

原始输出留档在 `docs/.balance-raw.txt`，用于后续 diff。

## 数值的两条入口

- **改数字** → `src/data/*.ts`（`attributes` / `damage` / `weapons` / `zombies` / `characters` / `run` / `scenes`）
- **改图表** → `src/sim/balance-check.ts`，然后 `npm run sim`，再把输出同步进 `02-数值表.md`

文档里的数字**全部**从模拟器导出，不手填——手填的表会和代码漂移，这一条已经被坑过一次。
82 个子关卡的刷怪表同理：没有手写的关卡配置，全部由 `scenes.ts` 的 `expandScene()` 推导。

## 模拟器能回答什么

**能**：清怪速率够不够、BOSS 血量锚点对不对、阵容之间有没有区分度、各乘区有没有写错、
**每个挑战维度有没有死胡同**（每个维度 ≥3 种答案形状、≥2 个定位可答）。

**不能**：会不会死人、难度手感对不对、走位有没有意义。原因是它的三个简化
（地图抽象成一维距离 / 索敌是单点最近目标 / 队员完全不走位）叠起来抹掉了整个生存维度——
详见 `docs/02-数值表.md` §10，那是全文最重要的一节。

还有一条**被证伪过的期待**：模拟器能证明"每个维度都有多种解"，
但**不能**证明"很多种组合真的可行"——12 个维度实际只收敛出 1 条真约束。
这条边界如实记在 `docs/00-决策清单.md` D0，不拿阵容枚举的数字当背书。

难度必须靠真人原型试玩验证，不是靠这张表。
